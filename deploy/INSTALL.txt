============================================================
UI Sequence Call -- Install / Service Setup
============================================================

This is a long-running Java process. Install is just three steps:

  1. Extract the release zip to the directory you want it to run from
  2. Edit UISequenceCall.properties with real DB credentials
  3. Run it -- either manually (run.cmd) or as a Task Scheduler task

The service has no concept of "installed vs not installed" -- it's just
one fat jar plus its properties file. Whichever directory you run it
from is the install dir. There's no separate copy step.

============================================================
PREREQUISITES
============================================================
* Java 21 JRE or JDK installed; either on PATH or accessible
  via $env:JAVA_HOME.
* SQL Server reachable from this machine, with the sequence object
  named in UISequenceCall.properties (default: dbo.seq_UI_Test).
* For the Task Scheduler mode: PowerShell 5.1+ run as Administrator.

============================================================
STEP 1: EXTRACT
============================================================
Extract the contents of the release zip to wherever you want the service
to live. Common locations:

    C:\Tools\UI_Sequence_Call\
    D:\Apps\UI_Sequence_Call\

After extraction the directory will contain:

    ui-sequence-call-1.0.0-jar-with-dependencies.jar
    UISequenceCall.properties
    run.cmd                    (cmd / double-click launcher)
    run.ps1                    (PowerShell launcher; passes any args to the jar)
    version.txt
    deploy\
        register_task.ps1
        unregister_task.ps1
        INSTALL.txt    (this file)

============================================================
STEP 2: CONFIGURE
============================================================
Open UISequenceCall.properties in a text editor and fill in real values
for db.url / db.user / db.password. Adjust other knobs as desired:

    # Database -- must match a real SQL Server instance
    db.url=jdbc:sqlserver://<host>:1433;databaseName=<db>;trustServerCertificate=true;
    db.user=<user>
    db.password=<password>

    # HTTP service
    http.port=8080
    ui.path=/sequence
    api.path=/api/next-sequence

    # UI copy
    ui.title=UI Sequence Call
    ui.subtitle=Click the button to fetch the next value from the configured SQL Server sequence.
    ui.button.label=Get Next Sequence Number

    # Sequence target
    sequence.schema=dbo
    sequence.name=seq_UI_Test

ui.subtitle accepts raw HTML (links, <br>, <strong>, etc.); ui.title and
ui.button.label are HTML-escaped at startup so use plain text.

============================================================
STEP 3 (OPTION A): RUN MANUALLY
============================================================
Three equivalent ways:

  * Double-click run.cmd in the install directory, OR
  * From PowerShell:    .\run.ps1     (any extra args pass through to the jar)
  * From any terminal:  cd <install-dir>
                        java -jar ui-sequence-call-1.0.0-jar-with-dependencies.jar

Open http://localhost:8080/sequence in a browser. Ctrl-C to stop.

============================================================
STEP 3 (OPTION B): REGISTER AS A SCHEDULED TASK (no third-party tools)
============================================================
From an elevated PowerShell:

    cd <install-dir>\deploy
    .\register_task.ps1 -InstallDir "<install-dir>" -StartImmediately

The task is named "UISequenceCall" (override with -TaskName), runs as
SYSTEM (override with -RunAsUser), and is configured to:
  * Auto-start at system boot
  * Restart on crash, every 1 minute, up to 999 times
  * Have no execution time limit
  * Capture stdout -> service_stdout.log
  * Capture stderr -> service_stderr.log
  * (Java's own log: UISequenceCall.log -- application + Jetty/Javalin output)

After registration:
    Get-ScheduledTask     -TaskName UISequenceCall   # status
    Get-ScheduledTaskInfo -TaskName UISequenceCall   # last run / result
    Start-ScheduledTask   -TaskName UISequenceCall
    Stop-ScheduledTask    -TaskName UISequenceCall

To remove the task cleanly (does NOT delete the install dir):

    .\unregister_task.ps1 -TaskName UISequenceCall

============================================================
STEP 4: VERIFY
============================================================
Open in a browser:
    http://localhost:8080/sequence

Click the button. You should see "Sequence: <number>". Each click
returns the next value from the configured SQL Server sequence.

Or from the command line:
    curl http://localhost:8080/api/next-sequence
    -> {"value":<n>}

Service status check (when running as a task):
    Get-ScheduledTaskInfo -TaskName UISequenceCall
    -> LastTaskResult of 0 = OK / running

============================================================
TROUBLESHOOTING
============================================================
* Service starts then dies -- check service_stderr.log and
  UISequenceCall.log in the install directory.
* "Port already in use" -- another process is using 8080. Change
  http.port in UISequenceCall.properties and restart.
* "Cannot connect to DB" -- verify db.* settings. Run manually with
  --log-output=console to see the connect error live:
       java -jar ui-sequence-call-1.0.0-jar-with-dependencies.jar --log-output=console
* "Run as Administrator" required -- you tried to register the task
  from a non-elevated PowerShell. Right-click PowerShell ->
  Run as Administrator, then re-run register_task.ps1.

============================================================
UPDATING TO A NEW VERSION
============================================================
1. Stop the running task (or close the console window):
       Stop-ScheduledTask -TaskName UISequenceCall
2. Replace the jar in the install directory with the new one (extract
   the new release zip and copy ui-sequence-call-X.Y.Z-jar-with-
   dependencies.jar over the old jar).
3. Compare the new release's UISequenceCall.properties against your
   live one and merge any new keys -- existing values stay yours.
4. Start the task again:
       Start-ScheduledTask -TaskName UISequenceCall

The scheduled task definition itself does NOT need to be re-registered
unless the path or jar filename changed.

============================================================
ROLLBACK / UNINSTALL
============================================================
1. Stop and remove the scheduled task (if registered):
       .\unregister_task.ps1
2. Delete the install directory.

No registry entries, no system-wide changes -- the task and the install
directory are the entire footprint.
